# MGTV admin: operational workflows for Sponsors, Advertising, Events, Awards, Moderation, Notifications, Users & Settings

## Context
Content/Media/Homepage are now interactive on a shared local store. The other eight pages are still static (hardcoded arrays, no-op Add/Edit buttons, "Preview only" banner) and several show money: sponsor revenue and package prices, campaign budget/spent/spend, ticket sold counts. This pass makes them usable local-only workflows, removes all monetary UI, and keeps everything on shared mock state. No backend, no external services, no publish/deploy. Subscriptions, Customers (plan field), Analytics, Discovery stay out of scope, apart from deleting money wording from the AdminApp page descriptions/breadcrumb that belong to these pages. Subscriptions remains "Preview only" and is labelled out of scope.

## Findings that shape the plan
- Only `content, media, homepage` are in the store; reducer, `load()` and `reset` hardcode them, and `load()` has no per-slice defaults (an old saved blob would give `undefined`).
- Router supports `/admin/<section>/<...parts>`; `useDirtyGuard`, `PageActions`, `Link`, Modal/Drawer, ConfirmDialog, Tabs, Badge, EmptyState, TextField/SelectField, MediaPicker and `.btn/.tbl/.grid-*` classes are reusable. AdminApp has a `WIRED` set and a special-case header only for `content`.
- Dashboard is hardcoded (not store-backed) and shows "Flagged Items"/"Content Items"; it will be derived from the store so it stays consistent after these flows.

## Architecture

### 1. Ops store (new, separate from the media/content store)
`src/admin/store/ops/` with its own `OpsProvider`/`useOps()` (inside `StoreProvider`), `useReducer`, localStorage key `mgtv-admin-ops-v1`, per-slice defaults on load, and `resetOps()` wired into the existing TopBar "Reset demo data" button (TopBar calls both resets). One generic action set to avoid 8 reducers' worth of boilerplate: `upsert(slice, entity)`, `remove(slice, id)` (only used for drafts/test data), `log(slice, entityId, entry)`. Every entity has a stable prefixed ID (`spo_`, `adv_`, `cmp_`, `evt_`, `awd_`, `nom_`, `rpt_`, `ntf_`, `usr_`) and an `activity: {at, actor, action, reason?}[]` history (actor = current mock admin, Jordan Rivera). Files: `types.ts`, `seed.ts` (migrated from the existing arrays, money fields dropped), `ops.tsx`, small `rules.ts` per module for validation/transitions (pattern copied from `store/validate.ts`).
- Cross-module links by ID: sponsors/campaigns/events reference content IDs (shows/events from the content store) and media asset IDs (brand assets, creatives, event media). Deleting/archiving content or deleting media checks these links (extend `mediaUsage` to include sponsor brand assets, campaign creatives, event media so the Media Library "Used by" and delete-block stay truthful). Campaign preview reuses `CustomerCard`.

### 2. Shared UI additions (`src/admin/ui/`)
- `ReasonDialog` (ConfirmDialog + required reason textarea, validation) used for rejections, dismissals, removals, cancellations, result release, send.
- `ActivityLog` list component, `StatusPill` using one status→colour map per module, `ListDetail` helper (list page + `/admin/<section>/<id|new>` detail via route parts, same pattern as `Content.tsx`), `Stepper` for the notification flow, `ProvisionalNote` banner. Reuse `Tabs`, `Modal`, `PageActions`.
- Destructive clutter: row actions are Edit + a "More" disclosure only where >2 actions; destructive actions live in the detail view behind ReasonDialog/ConfirmDialog.

### 3. Modules (each: list, `/new`, `/<id>` editor, status transitions, activity history, empty states, validation, dirty guard, toasts, URL-synced tabs)
- **Sponsors** (`pages/sponsors/`): organization editor (name, description, website, status Active/Inactive with reason on deactivate), Contacts (add/edit/remove contact with confirm), Brand assets (MediaPicker for image logos; kinds light/dark/mark), Associations (pick shows from content store and events from ops events; shown on both sides: the show/event detail panels list sponsors), Activity tab. Packages tab: tier name/perks only, price removed, labelled "Tiers are provisional until product defines them"; no pricing anywhere.
- **Advertising** (`pages/advertising/`): Advertisers (org + contacts + status), Campaigns editor: advertiser, name, placements (checkbox list of homepage sections and content items from store; editorial only), creative assets (MediaPicker, must be Ready image/video), start/end dates (validation end>start), preview of the placement (card + homepage-row preview via `CustomerCard`, labelled prototype), review panel with state machine **draft → in review → approved | rejected; approved → active (when started, via "Activate" simulation) → completed; rejected → draft (revise)**. Submit for review validates required fields + ready creatives; Approve/Reject require a reason (ReasonDialog); outcome banner shows who/when/why. Reporting: operational engagement only (impressions, clicks, view-through) per campaign, every block tagged "Mock data, not measured". All budget/spend/revenue/CTR-as-revenue UI deleted.
- **Events** (`pages/events/`): editor with details, format (In person / Online / Hybrid), venue or online URL state, timezone (IANA select), schedule start/end rendered with the chosen timezone, linked media (poster, replay asset, trailer) via MediaPicker. **Two independent state machines**: lifecycle (draft → scheduled → postponed(new date, reason) → cancelled(reason) → completed) and broadcast (not configured → scheduled → live → ended → replay available). Postpone/Cancel use ReasonDialog and surface a notice on the event; broadcast controls are simulated and can't go live for a cancelled event. Replay association: pick a Ready video asset, shown as "Replay linked". Ticket sold/capacity and price removed; the external ticket link field stays as a plain URL.
- **Awards** (`pages/awards/`): award program → Categories (add/edit/reorder/archive), Nominees (name, optional image via MediaPicker, linked content), Voting window (open/close datetimes, validation open<close, nominees ≥2 per category), Results release states **hidden → previewed → released → withdrawn** with a results preview (mock tallies labelled mock), validation checklist, and ConfirmDialog with typed summary for open voting / close voting / release / withdraw. No finalized voting rules: a "Voting rules: awaiting product decision" note, no eligibility/tie-break logic invented. Hardcoded "Oct 15" replaced by the configured window.
- **Moderation** (`pages/moderation/`): report queue (filter by status/priority/type) → report detail: context panel (reported content snapshot, reporter, reason, prior reports on the same item, history). Three actions with distinct outcomes: **Approve content** (report resolved, content stays live, reporter notified as mock), **Dismiss report** (report closed as no violation; reporter's report recorded, item flagged "dismissed" count), **Remove content** (content status → removed with reason code + note, reported item shows "Removed" everywhere, content actually becomes Unpublished/Archived in the content store when it references one). Each requires a reason; rows move to Resolved tab with outcome label instead of vanishing; activity log per report; Reopen supported.
- **Notifications** (`pages/notifications/`): 4-step composer (Compose → Audience & channel [segment, channel push/email/in-app] → Preview per channel → Test locally [shows a simulated device/inbox render, "Not sent"] → Schedule or Send). Send/Schedule are **simulated delivery**: outcome screen with mock delivered/opened counts, a persistent "MOCK DELIVERY. No message was sent to anyone" label, scheduled items listed with cancel. Templates: create/edit/use (prefills composer). History reads from the ops store, rows labelled Simulated. Drafts saved and reopened.
- **Admin users** (`pages/users/`): Invite (email + role with validation, duplicate check, pending state, resend/revoke), edit role (change with confirmation and activity entry), suspend/reactivate with reason, search/filter. Roles shown with a **"Provisional until the permission matrix is approved"** banner and a read-only capability preview table (example, labelled provisional). Denied-access state: a "View as" role switcher (Viewer/Editor/Moderator/Admin) in Settings/users that makes restricted actions render a clear "Your role can't do this" state (e.g. Viewer opening Users or Settings → denied-access panel), implemented through a `usePermission(action)` hook with a provisional example map.
- **Settings** (`pages/settings/`): Account (required-field + email validation), Notifications toggles, API Access removed or labelled unavailable (the fake key is dropped; no external services), saved/unsaved indicator, dirty guard, Discard actually reverts. Persisted in ops store.

### 4. Shell
- `AdminApp`: add the new sections to `WIRED`; generalize the header special-case so `/admin/<section>/<id|new>` gets the entity title + status badge + breadcrumbs from a per-module `titleFor(route)` registry. Strip money words from titles/descriptions/breadcrumb ("Commerce" group → "Partners & Events"? kept as a navigation rename only if cheap; otherwise leave the label and fix descriptions). Sidebar group rename for Sponsors/Advertising/Events/Awards stays as-is to avoid churn; Subscriptions keeps "Preview only".
- Dashboard: derive counts from stores (open reports, content by status, campaigns in review, upcoming events).
